# 安装与恢复

适用于兆能 ZN-M2。最低要求为原厂 256 MB 内存机型；1 GB 扩容机型已在真机验证，其他扩容容量以设备实际识别为准。镜像面向纯有线配置，不提供 Wi-Fi 或 USB 功能。

## 选择镜像

| 文件 | 用途 |
|:---|:---|
| `*-sysupgrade.bin` | 在受支持的 OpenWrt 系固件中升级 |
| `*-factory.ubi` | 在兼容的 U-Boot 刷机环境中写入固件 |

从 [Releases](https://github.com/osGex0o0II/ZN-M2-No-WIFI-Builder/releases) 选择对应构建线，并核对设备型号、内核及加速类型。不同构建线的镜像不可混用。

历史 Release 资产名可能仍含 `256M`；自 2026-11-18 起的新构建不再使用该标识。该标识只表示最低原厂内存基线，不是容量上限；1 GB 扩容机型同样可用。

## 下载校验

每个 Release 的说明包含对应文件的 SHA256。下载完成后，使用完整文件名核对摘要。

Windows：

```powershell
certutil -hashfile "固件文件名.bin" SHA256
```

Linux：

```bash
sha256sum "固件文件名.bin"
```

macOS：

```bash
shasum -a 256 "固件文件名.bin"
```

将输出值与对应 Release 中的 SHA256 逐字符比对。不一致时不要刷入。

## 从 OpenWrt 升级

1. 确认当前设备与目标镜像兼容，备份现有配置，并阅读目标版本的发布说明。
2. 在 LuCI「系统 → 备份/升级」中上传对应的 `*-sysupgrade.bin`。
3. 同一构建线升级通常可以保留配置；跨构建线、跨内核或切换加速栈时，选择**不保留配置**。
4. 等待设备完成写入和重启。升级期间不要断电。

SSH 升级需要先将正确的固件文件传至路由器，例如 `/tmp/firmware.bin`：

```sh
# 同线、兼容的升级：保留配置
sysupgrade /tmp/firmware.bin

# 跨构建线切换：不保留配置
sysupgrade -n /tmp/firmware.bin
```

执行前确认 `sysupgrade` 的设备兼容性检查结果；**不要用强制参数绕过校验**。跨线升级前的备份仅供人工参考，不应直接导入不同构建线。

保留配置升级后的管理地址、账户和网络设置可能与出厂默认值不同。

## 首次刷机

`*-factory.ubi` 仅适用于已经具备**兼容 U-Boot 刷机环境**的设备，不表示可以直接通过原厂固件升级页面写入。

从原厂系统转换可能涉及过渡固件、分区布局和引导程序更换。当前仓库未提供经过独立校验的过渡固件与 U-Boot 下载来源及 SHA256，故**不提供通用的分区写入命令**。

首次刷机前必须核实：

- 设备确为 ZN-M2，内存容量满足最低要求，NAND 分区布局与目标引导程序匹配。
- 过渡镜像、引导程序的来源、摘要及写入分区已确认。
- 已具备有效备份与硬件恢复手段。

若设备已有受支持的 U-Boot Web 界面，可依该引导程序的说明刷入对应 `*-factory.ubi`。不要套用其他设备或引导程序版本的刷机命令。

## 启动失败与恢复

| 情况 | 建议 |
|:---|:---|
| U-Boot Web 界面仍可访问 | 核对镜像及分区兼容性，使用该引导程序支持的恢复方式 |
| U-Boot 命令行仍可运行 | 根据已确认的分区映射和引导程序命令恢复 |
| U-Boot 自身无法启动 | 串口终端不能单独修复引导程序；可能需要适用的硬件烧录或调试方案 |

使用 UART/TTL 调试前须核实板载串口电平和引脚定义，不要连接未经确认的 VCC。禁止盲用 `mtd write`、`flash` 或分区编号。

无法确认分区布局或恢复方法时，应停止写入，先收集设备型号、启动日志与当前分区信息。
